# 0001. 画面の見た目に Pico CSS を使う

- ステータス: 採用
- 日付: 2026-10-11

## コンテキスト

画面は素の HTML 要素と最小限の CSS で組んでおり、サンプルとして「UI ライブラリには頼らない」方針だった。見た目を整えるにあたり、ライブラリを入れるかを決める必要があった。画面は Vite で HTML 1枚にまとめて GAS の `doGet` で配信するため、ライブラリはすべてその HTML に埋め込まれ、重いほど初回表示が遅くなる。画面は4つで、部品はボタン・一覧・入力欄・Markdown 表示だけ。

## 決定

Pico CSS（jade の配色）を使う。HTML 要素そのものに見た目が付くため、JSX の構造はほぼ変えず、ボタンの種類などの class を足すだけにする。Pico で足りない分（共通バー、メモ一覧の行、編集画面の2列、削除ボタンの赤）だけ `style.css` に書く。

## 結果

JS は増えず、配信する HTML は gzip で約 12 KB 増える。ダークモードは Pico が端末の設定に合わせて切り替える。Pico の CSS 変数（`--pico-*`）に依存するため、Pico のメジャー更新時は `style.css` の見直しが要る。

## 検討した代替案

- Tailwind CSS ＋ daisyUI: 見た目の自由度は高いが、全画面の JSX に class を書き足すことになり、サンプルとして読みにくくなる
- Mantine / MUI: 使わない部品の比重が大きく、4画面には重い
- 素の CSS を作り込む: 依存は増えないが、ボタン・入力欄・ダークモードを自前で揃える手間がかかる
